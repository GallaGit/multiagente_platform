# Roadmap de evolución

## Alcance

Este roadmap ordena aprendizaje y desarrollo del portafolio. No es un plan de lanzamiento, calendario comercial ni compromiso temporal. Cada etapa depende de evidencia de la anterior.

## Corto plazo — servicios medibles

### 1. Diagnóstico de Continuidad Operativa

**Propósito:** confirmar proceso, stack, línea base y un caso.  
**Activo reusable:** checklist, taxonomía, mapa de sistemas y métricas.  
**Puerta de avance:** cinco empresas del ICP-01 muestran el mismo patrón; tres aceptan métrica.

### 2. Sprint de Orquestación de Leads

**Propósito:** validar el MVP sobre P05–P07 y H01–H04/H14.  
**Activo reusable:** reglas, conectores, pruebas, dashboard de excepciones y runbook.  
**Puerta de avance:** resultado antes/después, coste de entrega y compromiso económico verificable.

### 3. Consultoría de Proceso y Gobierno

**Propósito:** resolver causas organizativas que la integración no corrige.  
**Activo reusable:** RACI, diccionario de datos, estados y playbook ICP-01.  
**Puerta de avance:** mejora sostenida de completitud/adopción.

### 4. Automatizaciones acotadas

**Propósito:** probar módulos de calidad de inventario, reporting o handoff.  
**Activo reusable:** biblioteca de módulos y límites técnicos.  
**Puerta de avance:** mismo patrón implantado en tres clientes sin rediseño sustancial.

## Medio plazo — recurrencia y especialización

### 5. Continuidad Operativa Gestionada

**Dependencia:** base instalada y telemetría.  
**Objetivo de aprendizaje:** frecuencia de fallos, horas de soporte, cambios de API y valor de prevención.  
**Puerta de avance:** mantenimiento aceptado, alcance controlado y retención observada.

### 6. Expediente Operativo Integrado

**Dependencia:** segmento común, requisitos aportados por especialista y stack definido.  
**Primer foco posible:** ICP-03 antes de lanzamiento/entrega o ICP-01 con back-office.  
**Puerta de avance:** completitud, versiones, retrasos y pagador demostrados.

### 7. Catálogo de conectores y controles

**Dependencia:** repetición de servicios.  
**Objetivo:** separar configuración de desarrollo y estimar coste por conector.  
**Puerta de avance:** despliegue repetible, monitorización y soporte predecible.

## Largo plazo — producto y plataforma

### 8. Control de Continuidad SaaS

**Dependencia:** stack homogéneo, catálogo limitado, mantenimiento recurrente y canal.  
**Alcance inicial:** un CRM, uno o dos canales y controles de excepción.  
**Puerta de avance:** onboarding sin proyecto, margen de soporte y retención.

### 9. Copiloto IA de Operaciones

**Dependencia:** fuentes gobernadas, permisos, evaluaciones y caso frecuente.  
**Alcance:** resumen y propuesta citados, con aprobación humana.  
**Puerta de avance:** exactitud, aceptación, tiempo y coste superiores a alternativa sin IA.

### 10. Plataforma Operativa Interoperable

**Dependencia:** SaaS validado, modelo de eventos, base instalada, partners y seguridad.  
**Secuencia:** API → conectores certificados → expediente → marketplace → IA como servicio.  
**Puerta de avance:** valor de red y TCO inferior a integraciones bilaterales.

## Gates transversales

| Gate | Evidencia mínima |
|---|---|
| Problema | Casos reales del mismo ICP y frecuencia observable |
| Métrica | Línea base, fuente y owner |
| Técnica | API/export, permisos, prueba y fallback |
| Comercial | Piloto pagado o compromiso verificable |
| Operativa | Tiempo, incidencias, excepciones y soporte |
| Repetibilidad | Tres implantaciones comparables |
| Recurrencia | Mantenimiento aceptado y uso sostenido |
| SaaS | Configuración sin proyecto y margen positivo potencial |
| IA | Evaluación, citas, supervisión y coste por tarea |
| Plataforma | Partners, seguridad y efecto de red |

## Decisiones de no avance

- No construir SaaS a partir de un único cliente.
- No ampliar a KYC, pagos o notaría para aumentar “ticket”.
- No usar IA para ocultar datos desordenados.
- No mantener conectores sin telemetría.
- No entrar en ICP-04 sin autonomía contractual.
- No generalizar resultados de grandes empresas a microagencias.

## Cadena recomendada

`Diagnóstico → Sprint de Leads → Automatizaciones → Gestionado → SaaS`

Ramas especializadas:

- `Consultoría → Gobierno del dato → Reporting/BI`
- `Diagnóstico documental → Expediente → Controles de cumplimiento`
- `Datos gobernados → Copiloto IA`
- `SaaS → API → Plataforma → Marketplace`

La ruta principal es reversible en sus primeras etapas y concentra aprendizaje antes de inversión de producto.
