# Reglas de decisión

## 1. Dos resultados, dos lecturas

- **Puntuación base:** atractivo estimado si las afirmaciones fueran ciertas.
- **Puntuación ajustada:** atractivo respaldado por la evidencia actual.

Una base alta y una ajustada baja no autorizan construir; señalan qué hipótesis merece una prueba barata.

## 2. Umbrales orientativos

| Puntuación ajustada | Decisión por defecto |
|---:|---|
| 75–100 | Candidata a piloto o priorización |
| 60–74,99 | Validar los supuestos críticos antes de invertir |
| 45–59,99 | Mantener en cartera solo con experimento barato y decisivo |
| Menos de 45 | En espera, reformular o descartar |

Los umbrales no anulan las condiciones eliminatorias ni garantizan inversión.

## 3. Mínimos por criterio

Para pasar a piloto deben cumplirse todos:

- Dolor del cliente ≥ 4.
- ROI para el cliente ≥ 3.
- Facilidad técnica ≥ 3.
- Escalabilidad ≥ 3.
- Ninguna condición eliminatoria abierta.
- Confianza global ≥ 0,70.

Para priorizar inversión después del piloto:

- Dolor del cliente ≥ 4.
- ROI para el cliente ≥ 4.
- Ticket medio ≥ 3.
- Evidencia de pago o compromiso equivalente.
- Puntuación ajustada ≥ 75.

## 4. Desempates

Si dos oportunidades quedan a menos de 3 puntos ajustados, se decide en este orden:

1. menor riesgo eliminatorio;
2. mayor confianza global;
3. evidencia de pago más fuerte;
4. menor coste del próximo experimento;
5. menor tiempo para obtener evidencia decisiva;
6. mejor acceso al segmento y a datos;
7. mejor encaje con capacidades existentes.

No se usa la puntuación base como primer desempate porque puede premiar supuestos optimistas.

## 5. Presupuesto por etapa

La inversión crece con la evidencia:

| Estado | Autorización recomendada |
|---|---|
| Borrador | Investigación documental y diseño |
| Por validar | Entrevistas y acceso a datos |
| En validación | Prueba técnica o prototipo limitado |
| Validada | Piloto controlado |
| Piloto | Implantación medida en pocos clientes |
| Priorizada | Construcción y comercialización por hitos |

Cada etapa debe tener límite de tiempo o dinero, criterio de éxito y criterio de parada.

## 6. Comité de decisión

Participación mínima:

- responsable de cliente o discovery;
- responsable técnico;
- responsable económico/comercial;
- responsable de riesgo cuando haya datos personales, pagos, firma, AML o decisiones automatizadas.

El defensor de la oportunidad presenta evidencia, pero no decide en solitario. Los evaluadores registran primero su puntuación individual.

## 7. Cadencia

- Revisión rápida: cada dos semanas durante validación activa.
- Revisión de cartera: mensual.
- Revisión completa de rúbricas y pesos: trimestral o ante cambio estratégico.
- Reevaluación extraordinaria: cambio normativo, cierre de API, nuevo competidor, fallo de seguridad o resultado material de piloto.

No actualizar una puntuación sin añadir la evidencia que justifica el cambio.

## 8. Estados finales

| Estado | Definición |
|---|---|
| Priorizada | Cumple umbrales y recibe recursos |
| En espera | Atractiva, pero depende de una condición o momento |
| Descartada | No compensa validar o construir con la evidencia disponible |
| Invalidada | La evidencia contradijo un supuesto esencial |

Toda oportunidad descartada o invalidada conserva la ficha. Debe indicar qué nueva evidencia permitiría reabrirla, si existe.

## 9. Errores que invalidan la comparación

- puntuar soluciones con segmentos diferentes sin declarar el segmento;
- asignar 5 por ausencia de información;
- tratar interés verbal como disposición a pagar;
- estimar ROI sin coste de adopción;
- confundir función anunciada con resultado demostrado;
- ocultar personalización dentro de “producto” y sobrevalorar escalabilidad;
- usar ticket deseado en lugar de contrato o presupuesto;
- cambiar pesos después de ver quién gana;
- promediar evaluadores sin investigar desacuerdos;
- utilizar decimales para aparentar una precisión que la evidencia no tiene.
