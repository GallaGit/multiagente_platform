# Checklist — Discovery comercial (90 días)

Checklist operativa derivada de [06-Plan-comercial-90-dias.md](../Orquestacion-Leads-Agencias/Estrategia-Comercial/06-Plan-comercial-90-dias.md) y [03-Que-decirles.md](../Orquestacion-Leads-Agencias/Estrategia-Comercial/03-Que-decirles.md).

**Objetivo:** convertir hipótesis de ICP, problema y compra en evidencia suficiente para decidir si hay oferta repetible. El panel lab HubSpot es **demo opcional** — no sustituye entrevista ni baseline manual en el CRM del cliente.

---

## Pre-requisitos (antes del día 1 de contacto)

- [ ] Mensaje central y variante por ICP redactados ([03-Que-decirles](../Orquestacion-Leads-Agencias/Estrategia-Comercial/03-Que-decirles.md))
- [ ] Guion de entrevista (10–15 preguntas de hechos, no pitch)
- [ ] Consentimiento para tomar notas / grabación acordado
- [ ] Aviso de privacidad y lista de supresión definidos
- [ ] CRM comercial interno (seguimiento cuentas, etapas, razones de pérdida)
- [ ] Mapa de flujo mínimo (registro → owner → SLA → excepción)
- [ ] Ficha de baseline manual ([06-metricas](../mvp/06-metricas.md))
- [ ] Documentado qué **no** se promete (sin ROI inventado, sin multi-flujo en piloto)
- [ ] Panel lab disponible solo como demo opcional ([README del repo](../../../../README.md))

---

## Días 1–15 — Preparación

### Oferta de discovery

- [ ] Tesis inicial O01/O02 seleccionada
- [ ] Lista: 30 independientes + 18 mixtas + 12 comercializadoras (objetivo)
- [ ] Dos o tres clústeres geográficos comparables
- [ ] Señal, rol y fuente registrados por cuenta

### Criterio de salida (día 15)

Antes de contactar, poder explicar por cada cuenta:

1. [ ] Por qué esa cuenta
2. [ ] A qué rol
3. [ ] Con qué canal y condición
4. [ ] Qué pregunta concreta
5. [ ] Cómo se registrará oposición o rechazo

---

## Días 16–30 — Discovery

### Actividad semanal

- [ ] Priorizar introducciones y conversaciones (no cold masivo sin cumplimiento)
- [ ] Entrevistas **sin demo** como regla por defecto
- [ ] Documentar último caso concreto por entrevista
- [ ] Pedir registros anonimizados o esquema cuando hay patrón
- [ ] Buscar casos negativos (“esto ya lo resolvemos con X”)
- [ ] Revisar lenguaje cada 5 entrevistas

### Plantilla de notas por entrevista

| Campo | Notas |
|---|---|
| Cuenta / rol | |
| Problema (palabras del cliente) | |
| Último caso concreto | |
| Frecuencia y consecuencia | |
| Baseline manual (si compartido) | % sin dueño, tiempo 1ª respuesta, etc. |
| Champion identificado | |
| Aprobador / firmante | |
| Acceso técnico plausible | CRM, canal, export |
| Evento de compra | |
| Objeciones | |

### Revisión semanal (marcar Sí/No)

- [ ] ¿Aparece el mismo problema sin inducirlo?
- [ ] ¿Existe frecuencia y consecuencia?
- [ ] ¿El owner es identificable?
- [ ] ¿El CRM actual ya lo resuelve?
- [ ] ¿Hay acceso técnico plausible?
- [ ] ¿Existe evento de compra?

### Decisión al día 30

- [ ] **Continuar** — ≥5 casos recientes convergentes en un flujo
- [ ] **Reformular** — problema real, otro proceso/ICP
- [ ] **Detener** — casos vagos, solución actual suficiente o impacto irrelevante

**Meta aprendizaje:** 10 entrevistas independiente + 8 mixta + 6 obra nueva (ajustar si acceso limita muestra).

---

## Días 31–45 — Cuantificación

Para las **3 mejores cuentas**:

- [ ] Evento inicial y final definidos
- [ ] Muestra extraída o acordada
- [ ] Baseline calculado y documentado
- [ ] Coste proxy estimado
- [ ] Champion, aprobador y firmante mapeados
- [ ] Integración y riesgo identificados
- [ ] Status quo vs módulos CRM existentes comparados
- [ ] Escenarios pesimista / base / optimista (optimista ≠ compromiso)

### Criterio de salida (día 45)

- [ ] Baseline reproducible
- [ ] Mecanismo económico plausible
- [ ] Owner dispuesto a revisar propuesta
- [ ] Prueba aislable (un flujo, un canal)
- [ ] Datos accesibles bajo condiciones aceptables

**Meta:** ≥3 cuentas con baseline manual.

---

## Días 46–60 — Prueba de solución

- [ ] Elegir intervención mínima según incertidumbre (prototipo, prueba técnica, concierge, simulación)
- [ ] Demo panel lab **solo** si cuenta calificada y tras discovery
- [ ] 2–3 pruebas técnicas (API/export/CRM) registradas
- [ ] Reunión con aprobador: baseline, coste, prueba mínima, reversibilidad, criterio de éxito

---

## Días 61–75 — Propuesta

- [ ] Propuesta a 2–5 cuentas: un flujo, una métrica, dos guardrails, precio fijo, salida
- [ ] Revisión final con aprobador antes de enviar
- [ ] Reacciones a alcance y precio comparadas (no cambiar ICP + mensaje + producto + precio a la vez)

---

## Días 76–90 — Piloto y decisión

- [ ] Piloto pagado firmado o iniciado (ver [CHECKLIST-piloto-pagado.md](CHECKLIST-piloto-pagado.md))
- [ ] Registrado: días por etapa, horas implantación, soporte, excepciones, disposición a continuar

### Decisión de cartera (día 90)

| Evidencia | Decisión |
|---|---|
| Piloto pagado + resultado + continuidad | Diseñar oferta repetible |
| Problema y baseline, sin pago | Revisar comprador, prioridad y precio |
| Pago, entrega no escalable | Rediseñar solución/servicio |
| Interés sin acceso ni compromiso | Cerrar o nutrir por evento |
| Registros contradicen el dolor | Invalidar o reformular |

---

## Cadencia semanal (resumen)

| Día | Acción |
|---|---|
| Lunes | Embudo, 10 cuentas, hipótesis por contacto |
| Mar–Jue | Entrevistas, análisis, demo solo calificadas, registro mismo día |
| Viernes | Revisar 5 notas, objeciones, experimentos, cerrar estancadas, 1 conclusión |
